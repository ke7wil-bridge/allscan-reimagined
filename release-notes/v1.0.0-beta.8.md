# AllScan Reimagined v1.0.0 Beta 8

Beta 8 is a prerelease built on the official AllScan v1.02 baseline. It is the first ASR Beta 8 package to combine the redesigned dashboard, qualified digital-bridge system, final Settings/Instructions surfaces, responsive work, and managed browser update/recovery workflow.

## Highlights

- **AllScan v1.02 baseline:** ASR remains a side-by-side overlay at `/asr/` while stock AllScan remains available at `/allscan/`. Existing AllScan accounts and node data are preserved.
- **Dashboard:** redesigned module layout with Favorites, Node Controls, Connection Status, Digital Bridge Status, five Talker Cards, module ordering, and browser-persistent display choices.
- **Favorites:** persistent panel, double-click connect, drag reorder, descriptions/colors, Supermon import, reset, and live connection/TX/scanning indicators.
- **Node Controls and Custom Commands:** Connect/Disconnect, remembered Disconnect Before Connect, per-action Permanent, custom DTMF command management, and Manage Kicks & Bans where authorized.
- **Talker Cards:** current plus four recent talkers with callsign, source/protocol, description, location, duration/time information, and monotonic identity handling so resolved digital callers are not replaced by generic transport identities.
- **Digital bridges:** standardized DMR, YSF, P25, NXDN, M17, D-Star/URF, and Zello cards with evidence-backed live direction, configured destination kept separate from traffic identity, Recent Activity, Connected Clients, and supported client administration.
- **Unified Net Bridge:** DMR, YSF, P25, NXDN, and M17 share private AllStar transport node 1999. Mode changes serialize ownership, coalesce newer selections, and wait for confirmed ownership before connection actions. Destination/TG/reflector/module remains mode-specific.
- **Settings:** final Beta 8 category-based Settings UI, bridge configuration, account/access controls, diagnostics, software update, rollback, and interrupted-update recovery.
- **Themes and menus:** shared Beta 8 menu hierarchy across themes. ST:ASL provides its locked four-control desktop header: Menu, Resources, Theme, and Lookup.
- **Support:** Support & Feedback for issue/question/feature submission plus the separate optional Donate to ASR contribution dialog.
- **Responsive UI:** automated desktop, tablet, phone portrait, and phone landscape qualification, including modal/menu boundaries and touch-target improvements. Final physical-device acceptance remains a release gate before publication.

## Browser installation and updates

- A one-time bootstrap installs a verified release package; routine updates are available to administrators through the browser.
- The updater performs preflight, downloads and verifies the declared package/checksum, stages the release, creates a rollback backup, runs the installer, and verifies post-install health.
- Failed installs after the update boundary automatically attempt recovery of the previous installation.
- Persistent update state allows Settings → System & Recovery to detect and repair an update interrupted by reboot, power loss, or browser closure.
- Rollback preserves user-owned state and exposes only validated previous ASR installations.

## Upgrade and preservation

The installer is designed to preserve node identity/configuration, the AllScan account database, Favorites, branding, credentials/secrets, bridge configuration/state, map cache, and other protected user data. Existing manual/shared bridges remain external unless explicitly adopted or created as ASR-managed bridges.

For an existing ASR installation, use the browser updater when offered. For a first installation, use the published bootstrap command from the release instructions. Browser updates intentionally stop at preflight if the underlying stock AllScan installation requires an interactive upgrade.

## Recovery and rollback

Normal update failures are handled automatically. Administrators can use **Settings → System & Recovery** to inspect rollback candidates or check for an interrupted update. Do not interrupt an active rollback. If browser recovery cannot complete, follow the manual recovery procedure in `docs/browser-install-update.md` from the repository/release documentation.

## Bridge prerequisites and limitations

Digital bridge cards require their corresponding bridge stack and credentials/configuration. Connected Clients and Kick/Ban controls appear only where the backend supports authoritative client management. The Unified Net Bridge requires its managed bridge runtime and reserves node 1999 as transport; node 1999 is not a digital destination or talker identity.

Beta 8 remains a prerelease. The automated responsive qualification is complete, but final physical phone/tablet touch acceptance must pass before the package is published as the release candidate/final Beta 8 artifact.
