# AllScan Reimagined v1.0.0 Beta 8

Beta 8 is the largest ASR update so far. It is a broad redesign of the dashboard, menus, instructions, Favorites, node controls, digital bridges, Settings, update/recovery system, and phone/tablet experience—not just a bridge update.

## Major dashboard redesign
- The dashboard is organized into movable modules for **Talkers, Node Controls, Favorites, Connection Status, and Digital Bridge Status**.
- Module/display choices are remembered in the browser.
- Cards, spacing, controls, status indicators, and touch targets were standardized and resized for better use of available space.
- Desktop, tablet, phone portrait, and phone landscape layouts received dedicated responsive work rather than simply shrinking the desktop page.

## Talker Cards
- Five dedicated cards keep the **current talker plus four recent talkers** visible.
- Cards can show callsign, source/protocol and node, description, location, duration, and transmission time when available.
- Digital identity handling was rewritten so resolved callers are not replaced by generic bridge/transport identities when a transmission ends.

## Favorites redesign
- Favorites are now a persistent dashboard module with a redesigned management experience.
- **Double-click to connect**, drag to reorder, edit descriptions/colors, and import compatible Supermon favorites.
- Connection, transmitting, and scanning indicators make live state easier to recognize.
- Reset Order and Reset Colors require confirmation to prevent accidental loss of customization.
- Favorites were reworked for compact phone layouts while retaining useful controls and readable status information.

## Node Controls, commands, kicks and bans
- Redesigned Node Controls provide direct **Connect, Disconnect, and Commands** controls.
- **Disconnect Before Connect** can be remembered; **Permanent** remains an intentional per-use choice.
- Custom DTMF command buttons can be created and managed in ASR.
- **Manage Kicks & Bans** is integrated where the connected backend supports authoritative control.

## Digital Bridge Status redesign
Beta 8 substantially rewrites bridge management and presentation.
- Bridge cards were **resized and standardized** for more consistent desktop and mobile layouts.
- Common fields include Talking/Idle state, Last Talker, Connected Clients, and Recent Activity where supported.
- Status pills, warnings, menus, client-management controls, and spacing were standardized across bridge types.
- Supported bridges provide **Manage Clients / Kick / Ban** controls when authoritative client information is available.
- Runtime status is based on actual bridge evidence rather than merely assuming a configured bridge is online.
- Independently installed YSF/P25/NXDN/M17 reflectors that use ASR's verified
  UDP administration proxy now retain real remote clients even though the
  reflector sees the proxy transport as loopback. One node-owned bridge
  session is excluded, client addresses remain private, and the remaining
  identities are available to Connected Clients and supported Kick/Ban controls.

### URFWIL Standard Bridges
ASR can manage/display standard bridges grouped under **URFWIL** for **DMR, YSF, P25, NXDN, and M17**. These remain independent standard bridges rather than modes of the Unified Net Bridge.

### Unified Net Bridge
- A new **Unified Net Bridge** allows DMR, YSF, P25, NXDN, or M17 to use one private AllStar transport, one mode at a time.
- Each mode retains its own destination/TG/reflector settings.
- Private node **1999** represents the permanent transport. Seeing 1999 in Connection Status means the transport exists; it does **not** mean an outside digital destination is connected.
- Mode switching, runtime ownership, recovery, and reboot behavior were hardened and qualified.

## Bridge Setup Wizard and recovery
- Guided flow covers system detection, bridge settings, setup checks, preview, installation/configuration, and health testing.
- Managed bridge runtimes preserve configuration through supported upgrades/reprovisioning and recover after reboot.
- Recovery controls were added for managed bridge failures and interrupted provisioning.

## Completely redesigned Settings
Settings was reorganized into a clearer category-based interface rather than a collection of scattered controls. It brings bridge configuration, accounts/access, diagnostics, software updates, rollback, and recovery into one administrative experience.

## In-browser updates, rollback and recovery
Beta 8 introduces ASR's managed browser maintenance workflow.
- Administrators can **check for and launch supported ASR updates from the browser**.
- Update preflight checks the installation before making changes.
- Release archives and checksums are downloaded and verified before installation.
- A rollback backup is created before crossing the update boundary.
- Failed/interrupted updates can be detected and recovered.
- Valid previous ASR installations can be presented as rollback targets.
- Protected user data—including node identity/configuration, AllScan accounts, Favorites, branding, credentials/secrets, and bridge configuration/state—is designed to survive supported upgrades.

## Rewritten menus and navigation
- The Beta 8 menu/navigation system was redesigned and consolidated into a **shared menu hierarchy across all themes**.
- Navigation was cleaned up so the same functions are found in consistent locations regardless of theme.
- The **ST:ASL** theme keeps its dedicated Star Trek presentation while using the shared navigation structure; its desktop header intentionally has **Menu, Resources, Theme, and Lookup**.
- Menu/modal behavior and boundaries were reworked for touch devices and small screens.

## Rewritten Instructions and help content
- The built-in **Instructions/help content was substantially rewritten and reorganized** for Beta 8.
- Instructions now reflect the redesigned dashboard, menus, Settings, Favorites, controls, bridge features, update/recovery workflow, and current terminology rather than older ASR behavior.
- Installation/update guidance was revised around the supported packaged-release and browser-update workflows.

## Support & Feedback
- Built-in **Support & Feedback** lets users report an issue, ask a question, or suggest a feature from ASR.
- A separate optional **Donate to ASR** dialog is available for users who want to support development.

## Phone and tablet redesign
Beta 8 includes extensive responsive acceptance work: full-width primary modules where appropriate, compact Favorites, resized bridge cards, improved Connection Status spacing, larger/reliable touch targets, constrained menus/modals, and dedicated portrait/landscape behavior.

## AllScan compatibility
ASR remains side-by-side with stock AllScan at `/asr/` while stock AllScan remains available at `/allscan/`. Supported upgrades preserve existing AllScan account/node data rather than replacing it.

## Install or upgrade
For an existing supported Beta installation, use the browser updater when Beta 8 is offered. For a new installation, or to apply a corrected Beta 8 package to a node that already displays Beta 8, run:

```bash
curl -fsSLo /tmp/asr-bootstrap.sh https://raw.githubusercontent.com/ke7wil-bridge/allscan-reimagined/main/bootstrap.sh && sudo bash /tmp/asr-bootstrap.sh
```

The browser updater may not offer a corrected package when its displayed
version is unchanged. The bootstrap selects the published release, verifies
its checksum, creates a rollback backup, and starts the packaged installer.

Do not copy a Git checkout over an installed ASR release. Use the published package/bootstrap or the supported browser updater.

## Known limitations
- D-Star is intentionally coming in Beta 8.1 rather than Beta 8.
- Connected Clients and Kick/Ban controls appear only when a backend can provide authoritative client information/control.
- Some bridge types require operator/service credentials or configuration before they can connect.
- RF/audio validation still depends on the operator's actual radio and bridge environment.
