# AllScan Reimagined Beta 8.7

Beta 8.7 includes the improvements originally planned for Beta 8.6.1, along with new scheduling tools, bridge improvements and safer software updates. These are the changes since the published Beta 8.6 release.

## Changes — AllStar dashboard and Favorites

- Open the native AllStar bubble chart directly from the dashboard, with improved layout, navigation and interaction.
- Restore the Favorites manager controls for adding, editing, deleting and organizing favorites.
- Improve Favorites synchronization between ASR and AllScan, including consistent ordering and scrolling when dragging favorites in either direction.
- Improve access to selected Favorites files and recovery from protected backups without silently switching to a different file.
- Keep the original AllScan v1.06 interface available alongside ASR, with both applications sharing compatible data.

## Changes — Talker cards and Recent Activity

- Restore and preserve Standard DMR, YSF, P25, NXDN and M17 talker cards through updates and configuration repairs.
- Show how long each connected client has been connected. A tilde (~) identifies an estimated minimum duration when the exact connection time is unavailable.
- Improve the tracking of DMR connections and disconnections, including rapid reconnects, using actual TGIF session information.
- Show genuine connection, disconnection and transmission events consistently in Standard ASR and ASR Plus; do not treat registration or keepalive traffic as a transmission.
- Keep recent transmissions in the correct order, move the newest completed talker to Last Talker 1 and retain identified recent talkers after a refresh.
- Keep real AllStar talkers visible without duplicating their audio as incoming digital talkers when a bridge relays it.
- Improve M17 talker cards so relayed AllStar audio and the local bridge callsign are not mistaken for a remote M17 station.
- Normalize unnecessary callsign suffixes in Recent Activity while retaining the identity needed to administer clients.

## Changes — Bridge connections, Net Bridge and recovery

- Improve automatic recovery of disconnected Standard Bridge links and prevent a failed recovery attempt from leaving a bridge keyed with a busy tone.
- Add optional recovery of required AllStar links, with progressively longer retry intervals when a connection remains unavailable.
- Improve M17 connection reliability, keepalive handling and recovery.
- Keep M17 Net Bridge connections under manual operator control rather than automatically selecting a reflector when no connection was requested.
- Improve DMR bridge startup readiness and the identification of individual DMR sessions.
- Show Current Reflector for P25 and Current TG for NXDN on Net Bridge controls, on both traditional and container installations.
- Improve bridge setup and runtime health checks on container installations, including safe restoration of a disconnected M17 bridge after rollback.
- Prevent retired URF components from being accidentally reinstalled during software updates or configuration repair.

## Changes — Kick and Global Ban

- Improve DMR Kick so the selected station is disconnected from TGIF instead of merely disappearing from the client list.
- Improve Zello Kick so the selected talker is muted for one minute.
- Retain Global Ban protection for local and other protected identities, timed ban expiration, and the previously accepted bridge controls.
- Keep listing, adding, removing and expiring Global Bans working even when a bridge does not support local ban enforcement.
- Clearly identify bridges where a ban cannot be enforced. Outbound connections to external YSF, P25 or NXDN reflectors without a local administration adapter cannot enforce bans on those remote reflectors; this is now reported as partial enforcement rather than success.

## Changes — Admin Scheduling (beta)

- **Beta feature:** Admin Scheduling is still in beta. Please try it carefully and report unexpected behavior through Support & Feedback in ASR.
- Manage scheduled AllStar connections from the Admin area, including Connect, Monitor, Local Monitor and Disconnect.
- Choose a node directly or from Favorites, set connection durations, and repeat schedules daily or on selected days.
- Create, edit, enable, disable and delete schedules, with local time and daylight-saving handling.
- Preview a dry run without making connections; view scheduler health, recent execution history and whether the scheduler is running.
- Share the native AllScan schedule instead of running two competing schedulers. Scheduling is disabled by default on new installations and must be enabled by an administrator.
- Browse existing system timers, including inactive and disabled timers, and supported timers belonging to individual users.
- Enable, disable, start, stop or restart eligible timers, or run their associated service on demand.
- Edit supported timer schedules and create ASR-managed timers without overwriting the original timers supplied by other software.
- Protect critical timers and require confirmation for sensitive changes, with backups, change history and rollback safeguards.

## Changes — Software updates, backups and reliability

- Recover automatically from temporary network interruptions or an expired dashboard session instead of getting stuck at Verifying Dashboard Access.
- Improve the update process on systems with limited temporary disk space or restricted temporary directories.
- Correct browser rollback behavior and improve recovery when an installation or update fails.
- Preserve users, Favorites, branding, bridge settings, credentials and scheduler data through upgrades, rollback and reboot.
- Restore scheduler file access correctly after both manual and automatic rollback so existing schedules remain visible and usable.
- Install the required scheduling service (cron) when missing without turning on connection scheduling.
- Improve diagnostics for AllStar/IAX2 audio stalls and link problems, with more reliable monitoring and log handling.
- Strengthen release checks and ensure the installed version, dashboard, update notifications and packaged release information agree.

## Changes — Container-managed updates

- Add support for administrator-controlled browser updates on properly configured Docker/container installations, alongside traditional node updates and notification-only host-managed updates.
- Verify downloaded release files before installing them and back up persistent data before replacing the ASR web container.
- Leave the Asterisk container and host bridge services running during a web-container update.
- Check the updated dashboard before accepting the new version; automatically restore the previous image and data if the update fails.
- Protect update actions so only authorized administrators can request them, without granting the web container direct control over Docker.
- Preserve AllScan data, ASR settings, bridge configurations, uploaded web data and persistent runtime state.

## Changes — ASR Plus and multi-hub security

- Strengthen authentication and restrict API access tokens to their intended permissions.
- Improve protection against replayed commands, incorrect hub identities and unauthorized distributed control requests.
- Retain compatibility with existing supported login sessions while adding security regression checks.
- Improve secure telemetry and audit handling for multi-hub operation, including preparation and isolated testing for additional hub installations. This does not mean new hubs have been deployed.

## Upgrade notes

- Admin Scheduling is a beta feature and must be enabled explicitly. Existing schedule and timer settings are preserved.
- Container-managed browser updates require the one-time host setup described in `docs/container-browser-updates.md`. Traditional installations do not require Docker.
- Optional required AllStar link recovery should not be configured for a node that already has a permanent startup link in Asterisk.
- Nodes still using the retired URF reflector must migrate before installing this release.

## Installation / update

After Beta 8.7 is published, use the ASR dashboard's software update option where available. For a first installation or terminal recovery, use:

```bash
curl -fsSLo /tmp/asr-bootstrap.sh https://raw.githubusercontent.com/ke7wil-bridge/allscan-reimagined/main/bootstrap.sh && sudo bash /tmp/asr-bootstrap.sh
```
