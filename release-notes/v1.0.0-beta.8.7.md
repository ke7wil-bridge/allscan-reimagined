# AllScan Reimagined Beta 8.7 — Release Candidate

**Release candidate only:** publication and production deployment require separate owner approval after the remaining manual acceptance gates pass.

Beta 8.7 replaces the planned Beta 8.6.1 release in full. It retains every integrated Beta 8.6 and Beta 8.6.1 feature and fix; the historical release notes remain available separately.

## Changes — Admin Scheduling and systemd timers

- **Beta feature:** Admin Scheduling is still in beta. Please try it carefully and share feedback, including any unexpected behavior, through Support & Feedback in ASR.

- Keep native AllScan v1.06 connection scheduling under authenticated ASR Admin, disabled by default on fresh installations, with one native schedule store and one cron runner.
- Support schedule create, edit, enable/disable, deletion, Favorites/node selection, recurrence, durations, timezone/DST handling, dry runs, heartbeat, and bounded execution history.
- Discover inactive, disabled, static, generated, transient, package, system, and supported user-manager timers.
- Enable, disable, start, stop, restart, and safely run the single associated service for eligible existing timers.
- Edit eligible vendor schedules only through ASR-owned drop-in overrides. Never replace or delete vendor unit files.
- Support validated calendar and monotonic schedules, exact typed confirmations, critical/dependency protection, root-only backups, safety rollback, manager reload and complete mutation audit records.
- Restrict new and deletable timer definitions to the `allscan-reimagined-admin-*` namespace and reject arbitrary commands or file paths.

## Changes — AllStar dashboard and compatibility

- Preserve stock AllScan v1.06 at `/allscan` and ASR enhancements at `/asr`, including native scheduling compatibility and migration safeguards.
- Retain native AllStar bubble charts with improved navigation, layout, interaction, and regression coverage.
- Retain Favorites creation, editing, deletion, safe synchronization, ordering, and symmetric drag scrolling.
- Preserve one native connection scheduler and prevent duplicate cron execution across installation, update, reapply, and rollback.

## Changes — Talker cards, bridge activity, and identity

- Preserve standalone DMR, YSF, P25, NXDN, and M17 talker cards through upgrade and reapply.
- Retain persistent protocol activity, DMR identity/callsign behavior, connection transitions, and bounded Recent Activity history.
- Keep genuine AllStar talkers visible, filter outgoing bridge relay echoes, and preserve four identified Last Talkers after refresh.
- Retain Kick and Global Ban safeguards, Zello enforcement hooks, protected identities, duration expiry, and retired-URF protections.

## Changes — Updates, security, and reliability

- Retain idle authentication recovery, corrected rollback navigation, executable/low-space updater staging, and release integrity checks.
- Retain bridge recovery, persistent monitor reliability, IAX2 stall diagnostics, and bounded rotation-safe log readers.
- Retain ASR Plus scoped-token, replay, session-authentication, telemetry-identity, and distributed-command security work.
- Preserve bridge, user, Favorites, scheduler, cron, credential, and node configuration through installation, update, rollback, reapply, and reboot workflows.
- Keep packaged, installed, API, compatibility-overlay, and browser update metadata synchronized at Beta 8.7.

## Changes — Container updates

- Adds `ASR_UPDATE_MODE=native|external|container`, selected at container startup without editing application source.
- Keeps `native` behavior unchanged for traditional installations and retains `external` notification-only mode for host-managed containers.
- Routes `container` update requests through the existing Unix-socket host broker. The web container never receives the Docker socket.
- Verifies the published release archive and SHA-256 companion, builds a versioned image, stops the web tier for a consistent backup of all four persistent volumes, recreates only the ASR web service, and runs version and served-page health checks.
- Automatically restores the previous image and persistent volumes when replacement or health verification fails.
- Rejects unauthenticated browser requests, cross-origin update attempts, unsupported broker operations, and peers that do not match the configured web identity.
- Preserves AllScan data, ASR configuration, bridge configuration, uploaded web data, and ASR persistent runtime state. Host bridge services and the Asterisk container are not recreated.

## Upgrade notes

- Container hosts require the one-time broker and Compose bootstrap documented in docs/container-browser-updates.md.
- Scheduler activation remains an explicit administrator action. Installing Beta 8.7 does not enable connection schedules or add duplicate cron entries.
- Existing timer definitions and ASR-managed overrides are preserved. Critical timers remain protected even for administrators.
- `requiredAllStarLinks` remains optional. Do not configure the same node there and in app_rpt `startup_macro`.
- Nodes that still run a URF reflector must migrate before installing this release.

## Qualification status

- Prior integrated-candidate qualification evidence is retained, but the changed Beta 8.7 artifact must be rebuilt and requalified.
- Required acceptance includes authenticated desktop/mobile Admin Scheduling, guarded timer management, a genuine prior-version upgrade with seeded persistence, rollback, reboot, and stock AllScan compatibility.
- Issue #200 remains open until required tester acceptance and owner approval. Publication is not authorized by this candidate.

## Installation / update

Use the ASR dashboard browser-based update workflow only after this release is published. For a separately authorized first install or terminal recovery, use:

```bash
curl -fsSLo /tmp/asr-bootstrap.sh https://raw.githubusercontent.com/ke7wil-bridge/allscan-reimagined/main/bootstrap.sh && sudo bash /tmp/asr-bootstrap.sh
```
