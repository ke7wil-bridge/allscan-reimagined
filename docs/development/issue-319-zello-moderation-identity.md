# #319 — Zello moderation identity boundary
Observed live collector schema: recent_users records expose name, last_seen and last_seen_epoch only; no separate canonical account identifier in those records. The current bridge-local Kick implementation validates the selected name against recent/current talker state, writes an exact keyed JSON mute hold, and retains the 60-second contract across stream_stop. The global policy is not a safe arbitrary-name store: its line reader splits on whitespace/comma and downstream native adapters, TGIF, ASL and sudoers use narrow token contracts. Relaxing the regex alone could ban the wrong station (e.g. TAURUS instead of TAURUS 78).

First phase: allow existing backend-supported exact Zello identities through the Zello-specific UI without callsign-only or suffix-stripping transformations. No change to general callsign validation. Kick now accepts exact ASCII names with spaces and the observed runtime-supported punctuation (up to 48 characters) using a versioned-in-scope hex token over the existing sudo argument boundary. Decoding is restricted to the Zello Kick path; tests prove TAURUS 78 never mutes TAURUS and the hold survives stream stop. Global Ban of spaced names remains unsupported pending the end-to-end policy design.

Next phase: establish exact stable identity from Zello stream evidence; define lossless, typed policy representation (no whitespace token truncation, no namespace collisions), safe privileged argument transport, exact runtime match, expiry/audit/readback and explicit per-backend enforcement reporting. Preserve the existing radio/AllStar protected-identity and wildcard semantics. Test against multiple distinct names sharing the same first token, case, punctuation, control characters, shell metacharacters, legacy rules, upgrades and rollback. No live users kicked or banned in testing.


## Read-only MasterHub source inspection
The running Zello bridge source receives `from`, `user`, `username` or `display_name`, then its existing cleaner trims, substitutes whitespace, removes characters outside ASCII letters/digits and space/@/./_/\#/+/colon/hyphen, and truncates to 48 characters. The recent roster exports the resulting name, not an independently verified account ID. Kick must match that exact existing runtime key, never guess a callsign from a display name. Hex transport is limited to that character set and length; the existing radio-policy token parser remains unchanged. Do not equate a displayed Zello name with a radio callsign without evidence. For non-mappable names, cross-protocol enforcement cannot be certified; a typed rule design must disclose that limitation instead of truncating the rule or asserting verified global enforcement.
